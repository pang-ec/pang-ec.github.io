GitHub 계정 이전 시
겪은 인증 오류 해결 기록

2026.06.18 트러블슈팅

기존 GitHub 계정(choec77)을 동료들이 찾아내면서, 급하게 새 계정(pang-ec)으로 포트폴리오 리포지토리를 이관해야 했다. 헤드리스 리눅스 서버에서 작업하다 보니 인증 단계에서만 두 번 걸렸다.

첫 번째 벽: 브라우저 로그인이 안 먹힘

gh auth login을 실행하면 원래는 브라우저가 열리면서 로그인 화면이 뜨는데, 브라우저가 없는 서버에서는 이렇게 실패한다.

exec: "xdg-open,x-www-browser,www-browser,wslview":
executable file not found in $PATH

해결은 Personal Access Token을 직접 발급해서 환경변수로 넘기는 방식.

export GH_TOKEN=ghp_xxxxxxxxxxxx
gh auth status

이렇게 하면 브라우저 없이도 gh CLI가 바로 로그인 상태가 된다.

두 번째 벽: gh는 로그인됐는데 git push가 안 됨

gh auth status는 정상인데, 정작 리포지토리를 새로 만들고 push하려 하면 이런 에러가 났다.

remote: Invalid username or token. Password authentication
is not supported for Git operations.
fatal: Authentication failed

원인은 간단했다 — gh CLI의 인증과 git 명령어의 인증은 별개다. gh가 로그인돼 있어도 git push는 그 정보를 자동으로 물려받지 않는다. 연결해주는 명령어가 따로 있다.

gh auth setup-git

이 한 줄을 실행한 뒤부터는 git push, git pull이 토큰 기반으로 조용히 통과됐다.

이관이 실제로 됐는지 확인하는 법

push 명령이 에러 없이 끝났다고 바로 안심하지 않고, 두 가지 방법으로 다시 확인했다.

# 로컬 커밋과 원격 브랜치 로그 비교
git log new-origin/main --oneline -5

# 브라우저 URL 확인 (헤드리스 서버에선 링크만 출력됨)
gh repo view pang-ec/ncp-mcp-server --web

로컬 로그와 원격 로그의 커밋 해시가 같으면 정상적으로 이관된 것이고, 안전하게는 브라우저에서 실제 README와 커밋 목록을 눈으로 한 번 더 확인했다.

부가적으로 만난 스코프 경고

이관 도중 조직(Organization) 관련 작업을 시도할 때 이런 경고가 떴다.

Missing required token scopes: 'read:org'
  - To request missing scopes, run: gh auth refresh -h github.com

확인해보니 이건 조직 소유 리포지토리를 다룰 때만 필요한 스코프였고, 개인 계정 간 리포지토리 이관 작업에는 영향이 없어서 무시하고 진행해도 문제없었다.

남은 흔적: 커밋 author는 안 바뀐다

레포를 통째로 옮겨도 과거 커밋에 박힌 author 이메일은 그대로 choec77 계정으로 남는다. 코드 내용만 이동할 뿐 커밋 히스토리 안의 메타데이터까지 새로 쓰지는 않기 때문이다. 완전히 지우고 싶다면 새 리포지토리를 만들고 .git을 초기화한 뒤 깨끗한 히스토리로 다시 커밋하는 방법을 썼다 — 과거 이력을 남길 필요가 없는 포트폴리오 레포라 이 방식이 더 간단했다.

정리

  • 헤드리스 서버에서는 gh auth login 대신 GH_TOKEN 환경변수로 로그인
  • gh 로그인 후에는 반드시 gh auth setup-git으로 git 인증까지 연결
  • 과거 이력을 지우고 싶으면 새 .git으로 재초기화, 유지하고 싶으면 git filter-repo 사용
